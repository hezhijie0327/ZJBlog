# 定制旅行攻略（travel-guide）

为"已落定的定制行程"类文章生成与维护统一结构。基准范例：`content/blogs/hengdian-yiwu-national-day-guide.md`。新题材（温泉/古镇/海岛/亲子…）复用同一骨架，只换内容；骨架模板见 [references/template.md](references/template.md)，数据采集打法见 [references/data-playbook.md](references/data-playbook.md)。

## 工作流（先查后写，规则约束路线）

1. **锁定事实**：车票/酒店/门票逐项确认状态——已购的写「✅ 已购 + 实付价」，未购的给候选表 + 起售/抢票规则。
   - 高铁：内部浏览器查 12306 官网（具体步骤与坑见 data-playbook），车站按用户指定范围筛选。
   - 门票：打开 OTA 详情页核对票面权益——含哪些园/馆、**每园限进几次**、有效期口径、入园凭证；详情页海报常带「活动一览」「分区动线」「必看演艺」，直接吸收进行程。
   - 酒店/餐饮/寄存：多平台核实（地址、营业时间、排队策略、价格口径）。
2. **用硬规则排路线**：限次、有效期、演出时刻、堵车时段是约束条件。先列各点时刻表 → 找冲突（如 18:20 与 19:00 的两场演出）→ 给出"最顺的一个环"，冲突项写 **⚖️ 取舍说明**，不可兼得项给"挪到前一天/下次再来"的出路。
3. **写作**：按 template.md 骨架成文。语气 = 顶级定制旅行社行程单：**已落定口吻**（"主场日/收官日/压轴/零回头路"），不是比价攻略；待决策项收进第八节待办，不在正文里摇摆。
4. **质量门禁**：`pnpm build` 必须过（frontmatter + 内容管线 + 预渲染）；mermaid 语法正确；数字自洽——头部 💰 已落定支出 = 各分项实付之和 = 第七节合计。

## 文章骨架（头部 + 8 节）

硬性要求（完整模板见 template.md）：

- **frontmatter**：title 用「A × B 主题 X 日（出发地 · 全程已订版）」式；description 一句话卖点 + 已落定项；summary 以行程动线优先，含总花费与剩余待办；date = 最后核实日（每次大更新同步刷新）。
- **头部（速览卡模式）**：① tagline 一行 quote（情绪卖点）；② `## 🧭 行程速览`——TL;DR 表格（日期/路线/大交通/住宿/门票/预算/**还差几件事**），让读者 10 秒抓重点；③ `> [!info] 数据口径` callout（核实日期、"以出行当日官方公告为准"、订票背景）。**过程性信息不进正文头部**。
- **写法与富渲染**统一遵循 **md-style** skill（`.agents/skills/md-style/SKILL.md`）：callouts、mermaid gantt 时间轴、geojson 路线图、`<details>` 折叠备选信息、任务清单；富块全文 3-6 个，服务于扫读。
- **一、行程总览**：节奏设计一句（"D1 轻 / D2 重 / D3 顺"式）+ 三日一览表（天/主题/白天/夜晚/住宿）+ **geojson 路线示意图**（各站点 Point + 各段 LineString）+ 每日 `### D n｜日期（周几）· 主题日：…` 时间轴；bullet 以**粗体时间开头**，💘 情侣点、⚠️ 避坑、💡 tip 按需标注；主场日（信息最密的一天）加 mermaid gantt 全天时间轴；不可兼得的取舍写 `> [!important] 取舍说明`。
- **二、大交通**：已购车次表（✅ 已购 + 实付价）+ 备选表（仅供退改签）+ 起售/购票规则；末尾 **🚕 落地短驳**——只写"还需要的"本地接驳（站⇆酒店、跨区转场、返站时段），**不要**把已订掉的大交通备选写回来。
- **三、住宿**：已订 ✅（实付价 + 位置红利 2-3 条：到哪个景点步行、到美食街几分钟）。
- **四、定制三餐 & 采购清单**：三日吃饭表（天/午餐/晚餐，按车次与演出时刻落实）+ 必吃清单（附营业时间、排队策略）。
- **五、购物/活动路线**：铁律先行（如"只逛支持零售的"）+ mermaid `flowchart LR`（起点 → 分区 → 返程；有备选方案时画双分支）。
- **六、特色专题**：按题材（宠物/亲子/摄影…），给清单表与价格区间。
- **七、预算记账（实付 vs 预估）**：✅ 已购实付行、⏳ 待办预估行、**已落定支出**小计、**全包预估**合计（注明不含购物）。
- **八、出发前清单**：三组——✅ 已办结 / ⏳ 待办（按优先级）/ 🎒 出发当天。来源与参考文放在文末 quote + "主要参考笔记"小节，注明核实日期。

## 配图策略

攻略类文章**默认不配本地图**：多天行程的配图会让仓库资产膨胀，且真实场景图多为截图/网图，管理成本高于收益。确需配图时：① 优先使用稳定远程图源直链；② 或将原始 PNG/JPG 放 `public/images/<slug>/`，构建会用 sharp 自动压缩（限宽 1920，见 AGENTS.md「图片」），正文以 `/images/...` 引用。⚠️ 小红书等平台 CDN 图链带时效签名，**不可作为远程引用**。

## 更新既有攻略（"更新战况"类请求）

- 逐项替换状态：未购 → 已购（补实付价与 ✅），随之失效的"抢票警报/候补对策"删除或改写成战绩。
- **五处必须同步**：头部状态块、对应行程日、一览表、第七节预算、第八节清单——漏一处就会出现自相矛盾。
- 若新信息改变硬规则（如票面限次、场次时间），重排受影响的路线并更新 ⚖️ 取舍说明。
- 完成后 `pnpm build` 验证并提交，commit 用 `docs(blog): …` 描述行程变化本身。
